# Shinobi-mon

A Pokémon Showdown-style battle site starring the Shinobi Showdown roster. Every shinobi is a "mon" with types built from chakra natures, base stats converted from Shinobi Showdown, every Shinobi Showdown jutsu as a typed move, an ability and a hidden ability, and Mega-style transformations. Shinobi Showdown itself is a separate game and is unchanged.

The site layout and battle engine are forked from MARVEL-mon (VGC rules, level 50).

## How it plays

- **Formats:** Singles (bring 6, pick 3) and Doubles (bring 6, pick 4).
- **Quick Match:** 20 random shinobi (random natures, IVs and standard or hidden ability) → pick 6 → set up to 4 jutsu and an item each → teams revealed → secret lineup → battle. Against the CPU or another player.
- **Clauses:** one version of each shinobi per team (Naruto Part I and Naruto Sage Mode can't both be on a team) and one of each item.
- **Transformations (Megas):** a shinobi holding its transformation scroll can transform once per battle, one per team. HP stays the same; stats (+100 BST), types and ability change. Jutsu marked "only usable after the user transforms" (Night Guy, Tailed Beast Bomb…) unlock then.
- Battle clock, replays, stats, damage calc and private rooms work as on MARVEL-mon. Accounts, Competitive (Battle Pass rosters) and Road to 50 are switched off in the UI for now.

## Types

19 types: Fire, Wind, Lightning, Earth, Water, Yin, Yang, Wood, Ice, Lava, Storm, Magnet, Boil, Explosion, Dust, Taijutsu, Weapon, Beast, Sage. Super effective 2×, resisted 0.5×, no immunities, dual types multiply (4× to 0.25×). The chart is in `tools/source/typechart.json`. Status immunities: Fire can't be burned, Lightning can't be paralyzed, Weapon can't be poisoned, Ice can't be frozen.

## Data

Everything is generated by `npm run build:heroes` (`tools/build_shinobi.py`) from `tools/source/`:

| Source | What it is |
| --- | --- |
| `showdown_shinobi.json`, `showdown_jutsu.json` | The roster and jutsu exported from Shinobi Showdown |
| `typechart.json` | The type chart |
| `shinobi_types.json` | Type 1/2 for every shinobi and its transformation (with the reason) |
| `jutsu_types.json` | Types for jutsu that have no chakra nature |
| `art.json` | Which image in `public/images` belongs to each shinobi and transformation |

It writes `shared/fighters.json`, `shared/moves.js`, `shared/megas.js`, `shared/genders.js`, `shared/typechart.js` and `server/engine/abilities.js`.

**Stat conversion:** HP → HP, TAI → Atk, NIN → SpA, DEF → Def, SPD → Spe, SpD = 0.45·DEF + 0.3·NIN + 0.12·Chakra.

**Jutsu conversion:** taijutsu → Physical, ninjutsu/genjutsu → Special, support → Status. Power ×0.85 (rounded to 5, max 150). Burn/poison/paralysis carry over, Bind → paralysis, genjutsu → confusion (or sleep for long genjutsu), buffs/debuffs → stat stages, clones → Substitute, healing → recovery or drain. Every shinobi also learns Kunai & Shuriken, Substitution Jutsu (Protect) and Body Flicker (U-turn).

**Turn order:** like Pokémon, Speed decides who moves first. Only a few very quick jutsu have priority: +3 for Thousand Years of Death (Fake Out style, first turn only), +1 for weak, fast strikes (Kunai & Shuriken, Shuriken Volley, Senbon Volley, Hidden Needle Shot, Explosive Tag Kunai, Hair Needle Senbon, Dynamic Entry), +2 for Flying Thunder God Strike (Extreme Speed style), +2 for bodyguard moves and +4 for protecting moves (Substitution Jutsu, Palm Rotation…). The priority list is `PRIORITY` in `tools/build_shinobi.py`.

**Abilities:** hand-designed in `tools/ability_design.py`: an ability and a hidden ability per shinobi plus one per transformation, all lore-based. The build fails if two different abilities have the same effect. Descriptions are written from each ability's effects, so they always match what it does.

## Run

```
npm install
npm start          # http://localhost:3000
npm test           # mechanics, accounts, rooms, 400 CPU battles, 200 fuzz battles
```

## Deploy (Render)

`render.yaml` defines the web service. `SHINOBI_SECRET` is generated automatically. `DATABASE_URL` (Neon Postgres) is optional for now; without it, replays and stats live in memory and reset on restart.
